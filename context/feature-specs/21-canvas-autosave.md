## Canvas Persistence, Autosave & Blob Storage

## Goal

Implement canvas state persistence using a dual-storage design pattern. Project relational metadata lives in PostgreSQL via Prisma, while the rich, multi-user infrastructure canvas JSON graphs (nodes and edges) are serialized and persisted asynchronously to Vercel Blob Storage. This safeguards the system state before invoking intensive AI failure injections.

1. Storage Schema Validation

Review your existing prisma/schema.prisma configuration to verify compatibility with the artifact storage model:

- The Project model must utilize the canvasJsonPath String field (or an explicit canvasBlobUrl field) to maintain a secure string pointer reference to the Vercel Blob cloud container.

- Invariant: Database columns must only capture the string URL reference pointer; raw, un-parsed canvas layout JSON blocks must never be injected directly into relational PostgreSQL columns.

2. Persistence API Endpoints

Create a nested Next.js 16 Route Handler structure at src/app/api/projects/[projectId]/canvas/route.ts to manage remote I/O processing:

A. PUT /api/projects/[projectId]/canvas

- Authorization Guard: Call Clerk's auth() helper and invoke your lib/project-access.ts server handler. Reject request access with an HTTP 403 or 401 status if the user lacks write tokens.

- Blob Transaction: Serialize the incoming React Flow nodes and edges JSON payload. Stream the payload directly to cloud object storage using @vercel/blob's put() engine tool under an explicit workspace namespace (projects/[projectId]/canvas.json). Use the addRandomSuffix: false and overwrite: true configuration flags to continuously replace the singular master artifact file.

- Prisma Mapping: Capture the absolute secure HTTPS URL generated by Vercel Blob, and commit an asynchronous Prisma update query string setting the matching project's canvasJsonPath property field.

B. GET /api/projects/[projectId]/canvas

- Metadata Read: Query the database to retrieve the target project's canvasJsonPath string destination target. If unassigned, immediately return an empty canvas fallback object structure.

- External Payload Ingestion: Fetch the core application JSON content directly from the resolved Vercel Blob remote host target using the native server-side fetch() stream client wrapper. Return the resulting graph matrix structure array directly back to the requesting client editor component workspace.

3. Client Debounced Autosave Engine (src/hooks/use-canvas-autosave.ts)

Create a custom React lifecycle hook to track real-time graph changes without choking the external network pipeline or exhausting execution budgets:

- State Watchers: Monitor the core structural arrays of your canvas layout: the Liveblocks-synced nodes and edges matrices.

- Debounced Throttle Gateway: Intercept changes through a controlled timing buffer. Wait for exactly 5000ms (5 seconds) of complete operator idle time before allowing the state to flush downstream to the API route. This throttling layer prevents rapid, pixel-by-pixel node dragging movements from firing hundreds of unneeded cloud container writes.

- Status Indicators: Maintain a localized string status token ('idle' | 'saving' | 'saved' | 'error') to broadcast save states seamlessly onto UI tracking indicators.

4. Multi-User Hydration Strategy (Load Safety)

To prevent race conditions where a loading script accidentally overwrites active canvas edits being made by concurrent room participants, implement this strict loading logic inside your client wrapper:

- Room Evaluation Gate: Upon entering a room workspace, immediately evaluate the current Liveblocks room state.

- Conditional Injection Invariant:If the room already contains active nodes or edges: Completely skip the external Vercel Blob file retrieval routine. Trust the operational, real-time WebSocket state completely to prevent data clobbering.If and only if the Liveblocks room is entirely empty: Fire a one-time setup call to GET /api/projects/[projectId]/canvas. Hydrate the fetched nodes and edges directly into Liveblocks storage to establish the collaboration baseline for the new session.

5. UI Status Indicator Integration

Incorporate a clean, responsive status element directly inside your editor header layout toolbar space:

- Placement Context: Locate the tracking notification widget adjacent to the workspace execution controls or within the main navbar footprint.

- Visual Mappings:saving: Displays a muted spinning loader icon alongside text reading Saving changes....saved: Displays a subtle checkmark asset utilizing the --state-success green token reading All changes saved.error: Displays an alert icon utilizing the --state-error red token reading Save failed - Retrying.
